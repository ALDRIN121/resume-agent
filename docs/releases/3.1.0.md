# 3.1.0 — Reviewed memory and role decisions

Local release candidate, 13 November 2026. Nothing has been published or pushed. See the [C2 evidence](../superpowers/plans/2026-11-13-r2-acceptance.md).

The Memory page retains explicitly accepted fact corrections, targeting preferences and writing rules. Every proposal shows its source and exact before/after values. Rejection leaves active information unchanged. Revocation and replacement retain the audit. Interrupted saves compare original, proposed and current profile hashes before recovery. New runs freeze accepted rules; later changes leave earlier runs intact.

Jobs stores complete postings as immutable snapshots. Saving a job makes no model call. Evaluation records requirement quotes, candidate references, unknowns, separate eligibility and an advisory evidence interval. Six product-default weights use exact arithmetic. Missing evidence widens the interval; no usable criteria returns no score. Explicit eligibility facts and accepted hard constraints can establish conflicts. Personal identifiers and general location preferences cannot.

Users can inspect and override advice before tailoring. Stale inputs remain visible. Generation preserves the selected job snapshot and evaluation reference, with the existing content/PDF reviews. Direct paste, file and URL generation remain available. Saved non-secret forms survive reload, with reconciliation when revisions change.

Shared CLI commands include `jobs capture/list/inspect/tailor`, `evaluate`, `evaluations inspect/continue/cancel` and `memory propose/list/inspect/decide`. Memory decisions require a revision and action ID. Tailoring with stale or non-prioritized advice requires `--override`.
