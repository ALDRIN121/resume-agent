# Short reviewed-workflow demonstration

Use only the fictional files in `examples/job-search-demo`. Keep the demonstration in an isolated test state directory.

1. Set `RESUME_GENERATOR_STATE_DIR` to a new test directory before starting the application.
2. Import `profile.tex` through the app or agent skill.
3. Compare the complete source with the parsed draft.
4. Accept the draft only after that comparison.
5. Save the complete `job.txt` posting in Jobs.
6. Evaluate that selected role when desired.
7. Explain the evidence interval and any unknown requirements.
8. Start generation from that exact saved role.
9. Leave proposed changes unselected until the reviewer chooses them.
10. Inspect the complete content projection and declared omissions.
11. Confirm the selected content.
12. Open the preview PDF and check its facts and layout.
13. Approve the current PDF only after that review.
14. Compare the released PDF hash with the preview hash.
15. Open Applications and create a planned record for that role.
16. Show that PDF generation did not record a submission.

For discovery, use controlled fixture boards during a recording. Show complete, partial and failed scans separately. Explain that absence from a complete scan does not prove employer closure.

For host execution, show the structured model request and the separate human pause. Explain host and backend billing separately. Do not describe the workflow as universally free.

Use this sequence for a short recording. It does not measure first-use completion time. Volunteer pilots provide that evidence separately.
